Claude Housekeeper

A safe Claude Code home inspector. It shows what is known, what is missing, what is protected, and what is blocked before anything changes.

claude-housekeeper diagnose claude-housekeeper plan No files changed protected by rule

Run plan to see every finding with its path:, next step, and blocked actions. Run with --json for the stable machine-readable shape, or --redact to share output safely.

Install

git clone https://github.com/hemzaz/claude-housekeeper.git
cd claude-housekeeper
node scripts/claude-housekeeper.mjs diagnose
node scripts/claude-housekeeper.mjs plan --scope=registry
node scripts/claude-housekeeper.mjs diagnose --safe --redact

The plugin slash command is /claude-housekeeper:housekeep. The Node CLI also runs out-of-band when Claude plugin loading itself is broken.

First Wedge

Broken Hooks Find direct missing hook paths without executing hooks or editing settings.
Plugin Cache Drift Separate expected orphans from candidate stale cache and mark missing freshness keys.
Protected Local State Keep do-not-touch paths visible, explained, and excluded from action.

Safety Model

Surface first Housekeeper classifies what kind of thing it is before judging what is wrong.
Evidence before stance Findings say what is known, what is missing, and what claim level is supported.
Rollback is not a checkpoint Claude checkpoints are context only. Cleanup needs Housekeeper-owned rollback proof.

Do Not Touch

Protected rules are treated as a hard boundary. Housekeeper can still report a protected item, but it becomes non-actionable and future cleanup code must skip it.

{
  "doNotTouch": [
    {
      "path": "commands/net-cables.md",
      "reason": "hand-maintained local command"
    },
    {
      "path": "skills/jewelry-box/**",
      "reason": "private local skill experiments"
    }
  ]
}

Stances

Housekeeper reports posture before action. A severe finding can still be blocked. A high-confidence finding can still be protected.

inform   useful context, no action
watch    not urgent, may matter later
review   user intent matters
probe    live key required
protect  boundary or do-not-touch
prepare  plan can be drafted
repair   only after consent, snapshot, verification
block    not allowed under current evidence

Boundaries

Protected User-declared do-not-touch paths remain visible but non-actionable.
Probe Required Safe mode cannot claim live behavior; loader and behavioral keys need consent.
Blocked Unknown ownership, missing rollback proof, or checkpoint-only rollback stops action.
No Files Changed The first wedge is diagnostic. Mutation waits for explicit implementation approval and rollback proof.
