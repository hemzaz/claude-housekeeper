## §1 v0.4 buildable spec — overview

v0.4 ships six pillars in TASKBOARD order. P1 (learning loop) lands
first because P2/P3/P4 write to its files. P5 (JSONC v2) unblocks any
home with comments in `settings.json`. P6 (`--stream`) is the final
gate before release prep.

| Pillar | Status after T-D04 | Surface |
|---|---|---|
| P1. Learning loop | Schema field `learnSchemaVersion: "0.4"` (Q1 ruling) | `learning/refusals.jsonl`, `learning/applied.jsonl`, `learning/rollbacks.jsonl`, `learning/state.json`, `lock.history` (N6 carry) |
| P2. MCP rewrite beyond stripping | `--mcp-command-rewrite=` on `harden`; hard refusal on foreign-owner MCP entries (item 6) | `harden --target=settings.mcp_command_missing --mcp-command-rewrite=<old>=<new>` |
| P3. Plugin prune (audit-only) | 30-day default grace (Q3); `pruneGraceDays` config (item 5) | new `housekeeper prune` |
| P4. Non-settings surfaces | `hooks.config_dangling` is JSON-rewrite; `registry.command_dangling` lives in `clean`; `skills.entry_dangling` lives in `clean` (Conflict A) | `harden --target=hooks.config_dangling`; `clean --target=registry.command_dangling`; `clean --target=skills.entry_dangling` |
| P5. JSONC v2 | `jsonc-parser` adopted (Q4) | comment-preserving rewrites for `settings.json` |
| P6. Batch `--stream` | Fixed 50-item chunks (Q5) | `clean --batch=<n> --stream --confirm --yes` |

Six independently-shippable pillars, four new refusal classes minimum,
one new mutation kind (`json-rewrite`, Q2), one new subcommand
(`learn`), one new subcommand in audit-only form (`prune`). No
operation-manifest schema bump; report schema gains documented optional
fields only.

## §3 Resolved pipeline contracts

### §3.1 P1 — Learning loop

**On-disk layout** under `<home>/.claude/housekeeper/learning/`:

| File | Append protocol | Schema field |
|---|---|---|
| `refusals.jsonl` | One line per compose-time refusal from `composeCleanPlan` / `composeHardenPlan`. `O_APPEND` is atomic on POSIX (single write < PIPE_BUF). | `learnSchemaVersion: "0.4"` on every line |
| `applied.jsonl` | One line per terminal manifest at `verified` or `applied+partialApply`. Append happens after manifest is closed. | same |
| `rollbacks.jsonl` | One line per terminal rollback (`reverted`, `aborted`). | same |
| `state.json` | Counters + last-N false-positive markers. Rewritten in place (atomic write-temp + rename + fsync, reuses `snapshot.mjs` helpers) on `learn --mark-false-positive <op_id>`. | same |

**Write path:** `composeCleanPlan` / `composeHardenPlan` call
`appendRefusal()` on each refusal it emits; `executeCleanPlan` /
`executeHardenPlan` call `appendApplied()` after the manifest is
terminal; `executeRollbackPlan` calls `appendRollback()` on terminal
state. None of these holds the lockfile — JSONL append is independent
(see `v0.4-architect-memo.md §3.5`).

**Lock-history relationship (N6 carry-over):**
`<home>/.claude/housekeeper/lock.history` is a sibling JSONL appended
by `acquireLock` / `releaseLock` from `scripts/lib/lock.mjs`. Same
append protocol, same `learnSchemaVersion: "0.4"` field. Lives outside
the learning/ dir because lock events predate any mutation lane. T-099a
ships this.

**Read path:**

- `housekeeper learn` (no args) — one-screen 30-day summary:
  - Top 5 refusal classes by count
  - Top 5 cleaned-detector IDs by count
  - Last 10 rollbacks (op_id + reason + timestamp)
  - False-positive marker count
- `housekeeper learn --json` — emit the same structure as JSON for piping.
- `housekeeper learn --prune --older-than=<days>` — truncate JSONL to entries newer than the threshold; default never.
- `housekeeper learn --mark-false-positive <op_id>` — rewrite `state.json` to add the marker; surfaces on next `diagnose`.

**Diagnose decoration:** `falsePositiveSeenBefore: N` is a top-level
optional field on the finding object (item P2 ruling). Present only
when `state.json` shows the same `detectorId + path` pair has been
marked. No ranking change in v0.4 (suggestion engine = v0.5).

**Invariants:**
- JSONL is append-only; truncation only via `learn --prune`.
- Same redaction posture as `diagnose --redact` (home path collapsed; token-scrubbed).
- `learn --prune --older-than=0` is a refusal (`learn-prune-threshold-zero`); we require a deliberate day count.

### §3.2 P2 — MCP rewrite beyond stripping

**CLI:** `harden --target=settings.mcp_command_missing --mcp-command-rewrite=<old>=<new>`

**Compose-time pipeline** (extends `composeHardenPlan`):

1. Parse `--mcp-command-rewrite=` into `{ oldCommand, newCommand }`. Reject malformed values with `mcp-rewrite-malformed-arg`.
2. Resolve `newCommand` against `PATH` or treat as absolute.
3. Verify `newCommand` exists and has `+x` bit; otherwise refuse with `mcp-rewrite-target-missing` or `mcp-rewrite-target-not-executable`.
4. Locate the `mcpServers.<name>` entry whose current `command` matches `oldCommand`; if no match, refuse with `mcp-rewrite-source-not-found`.
5. **Threat mitigation (item 6):** check the finding's `surface.owner` classification (set by `surface.mjs`). If the entry is owned by a plugin or extension (not `user-hand-edit`), refuse with `mcp-rewrite-foreign-owner`.
6. Compose one `json-rewrite` op (per Q2) that sets `mcpServers.<name>.command = newCommand`.
7. Validate idempotency (apply-twice equality), output JSON validity, file shape (still `Object`).
8. Emit the plan.

**Refusal taxonomy (v0.4 additions for P2):**

| Class | Reason | Trigger |
|---|---|---|
| `PreApplyRefusal` | `mcp-rewrite-target-missing` | Resolved `newCommand` doesn't exist |
| `PreApplyRefusal` | `mcp-rewrite-target-not-executable` | Resolved `newCommand` lacks `+x` |
| `PreApplyRefusal` | `mcp-rewrite-source-not-found` | No `mcpServers.<name>` matches `oldCommand` |
| `PreApplyRefusal` | `mcp-rewrite-malformed-arg` | `--mcp-command-rewrite=` not in `<old>=<new>` form |
| `PreApplyRefusal` | `mcp-rewrite-foreign-owner` | Target entry's `surface.owner` not `user-hand-edit` |

### §3.3 P3 — Plugin prune (audit-only in v0.4.0)

**Detector** `plugin.unused_past_grace` in `audit.mjs`:

1. Walk installed plugins via the existing plugin-detection layer (`audit.mjs`).
2. For each plugin, read `installed-at` from the plugin cache metadata.
3. If `now - installed-at < pruneGraceDays` (default 30, configurable per item 5), skip.
4. Query `learning/applied.jsonl` for any entry whose `detectorId` or `path` touched the plugin's cache; if found within grace window, skip.
5. Best-effort shell-history scan for slash-command invocations (`/<plugin-name>:<skill>`); if found within grace window, skip. If the scan fails (history unreadable), set `historyAvailable: false` on the finding and emit refusal-class `prune-history-unavailable` for the related stance computation.
6. Emit `plugin.unused_past_grace` at `inform` stance.

**Subcommand `housekeeper prune` (audit-only):**
- Filters diagnose to `plugin.unused_past_grace` only.
- Formats as a table (one row per stale plugin).
- `--json` for piping.
- `--safe` accepted as a no-op (P1 ruling) — prune is read-only.
- In v0.4.0, no mutation flags. v0.4.1 adds `--confirm --yes`.

**Audit-only protocol** (per `v0.4-architect-memo.md §3.5`): v0.4.0 ships the detector and the audit subcommand. No mutation kind is added in v0.4.0. `learning/refusals.jsonl` accumulates non-event entries (prune findings raise no refusals), but `applied.jsonl` collects no prune entries either. This gives v0.4.1 a clean data window — any prune-related `applied.jsonl` entry post-v0.4.1 is an uninstall.

The split:

### §3.5 P5 — JSONC v2

**Parser adopted:** `jsonc-parser` (Q4 ruling).

**API used:** `parse()`, `modify()`, `applyEdits()`. `modify()` returns
an edit list against the original buffer rather than re-serializing the
AST — this preserves comments through round-trip.

**Refusal class rename:**

- `settings-jsonc-detected` (v0.3, refuses every JSONC home) → removed.
- `settings-jsonc-rewrite-failed` (v0.4) — fires only when the
  `jsonc-parser` round-trip diverges (byte-for-byte mismatch on
  identity patch against the parsed-then-applied output).

**Round-trip fidelity test (T-501):** 5 JSONC fixtures (single-line
`//`, block `/*`, comment between keys, trailing comma, comment inside
nested object). Identity patch (no-op edit) must yield byte-equal
output. Any divergence fails the test and prevents adoption.

**Plain-JSON behavior is unchanged.** Files without comments parse
through `JSON.parse` as before; jsonc-parser is invoked only when v0.3's
two-phase tokenizer flags `settings.jsonc_detected`.

### §3.6 P6 — Batch `--stream`

**CLI:**
```
clean --batch=<n> --stream --confirm --yes
```

- `--stream` is rejected when `n <= 50` (refusal `stream-redundant-for-small-batch`).
- `--stream` with `n > 50` produces a parent manifest and N sub-manifests.

**Chunking model (Q5 ruling):** fixed 50 items per chunk. The final chunk may be smaller.

**Composition:** `composeStreamPlan` is a generator yielding
`{ chunkIndex, targets: [{target, path}] }` objects. Each chunk
composes into a normal `CleanPlan` and goes through the full
compose → validate → snapshot → apply → verify lane.

**Per-chunk manifest:** Each chunk produces a sub-manifest stored under
the same operations directory with `parentStreamId: <streamId>`. The
parent manifest carries:
```
{
  schemaVersion: "0.2",
  streamId: "stream_20260518_xxxx",
  chunks: ["op_...", "op_..."],
  status: "verified" | "applied",
  streamPartial?: true
}
```

**Per-chunk failure handling:** on any chunk's failure, the stream
halts. The parent manifest records `streamPartial: true`. Completed
sub-manifests stay at `verified`. The
`housekeeper.interrupted_operation` detector (v0.3 Q3 mechanism)
surfaces the parent on next `diagnose`.

**Rollback by streamId (item P3 ruling):**
`housekeeper rollback --stream=<streamId>` rolls back every
sub-manifest in reverse chunk order. Each sub-manifest's existing
rollback contract applies. Per-chunk rollback by `opId` remains
supported for surgical recovery.

**New refusal classes for P6:**

| Class | Reason | Trigger |
|---|---|---|
| `BudgetRefusal` | `stream-chunk-budget-exceeded` | A composed chunk exceeds 50-file / 10-MiB snapshot budget |
| `EnvironmentRefusal` | `stream-resume-not-supported` | User attempts to resume a halted stream (resume deferred to v0.5) |
| `PreApplyRefusal` | `stream-redundant-for-small-batch` | `--stream` passed with `--batch=n` where `n <= 50` |

## §4 Refusal taxonomy delta (v0.4 additions)

Existing v0.3 taxonomy stays (per `v0.3-design.md §3.3`). New in v0.4:

| Class | Reason | Where it fires | User-facing `nextStep` |
|---|---|---|---|
| `PreApplyRefusal` | `mcp-rewrite-target-missing` | `composeHardenPlan` for `--mcp-command-rewrite=<old>=<new>` when new path absent | "Install the binary at <new> or pass an existing absolute path." |
| `PreApplyRefusal` | `mcp-rewrite-target-not-executable` | same, when new path lacks +x | "Run chmod +x <new> or pass an executable path." |
| `PreApplyRefusal` | `mcp-rewrite-source-not-found` | same, when no `mcpServers.<name>` matches old | "Run housekeeper diagnose --json and check mcpServers.<name>.command." |
| `PreApplyRefusal` | `mcp-rewrite-malformed-arg` | CLI parser | "Pass --mcp-command-rewrite=<old>=<new> with a single equals separator." |
| `PreApplyRefusal` | `mcp-rewrite-foreign-owner` | `composeHardenPlan`, owner check | "This entry is owned by a plugin or extension, not your hand-edited surface. Edit the owning source directly." |
| `EnvironmentRefusal` | `prune-history-unavailable` | `plugin.unused_past_grace` detector when shell history unreadable | "Shell history was unavailable; prune ran without invocation signal. Pass --safe or grant read access." |
| `BudgetRefusal` | `stream-chunk-budget-exceeded` | `composeStreamPlan`, per-chunk | "Reduce --batch=<n> or split into multiple stream invocations." |
| `EnvironmentRefusal` | `stream-resume-not-supported` | `runRollback` on a non-terminal stream | "Resume is not supported in v0.4. Roll back the stream with housekeeper rollback --stream=<id> and re-run." |
| `PreApplyRefusal` | `stream-redundant-for-small-batch` | CLI parser | "--stream is for batches > 50. Drop --stream or raise --batch=<n>." |
| `PreApplyRefusal` | `learn-prune-threshold-zero` | `housekeeper learn --prune --older-than=0` | "Pass a positive day count; --older-than=0 is rejected by design." |
| `PreApplyRefusal` | `settings-jsonc-rewrite-failed` | `json-rewrite` apply path when round-trip diverges | "JSONC round-trip diverged; this is a parser bug. File an issue with --json output." |

The v0.3 `settings-jsonc-detected` refusal is removed (JSONC homes are
now hardenable per Q4).

## §5 Module exports (architecture-level)

New modules introduced in v0.4. Each exports pure functions; no I/O at
construction (consistent with v0.2 module-shape convention).

### `scripts/lib/learning.mjs` (Phase 1)

| Export | Contract |
|---|---|
| `appendRefusal(home, entry)` | Append one JSON line to `learning/refusals.jsonl`. Adds `learnSchemaVersion: "0.4"` and ISO timestamp. O(1) on a hot path. |
| `appendApplied(home, manifestId, summary)` | Append one line to `learning/applied.jsonl` after manifest is terminal. |
| `appendRollback(home, rollbackId, summary)` | Append one line to `learning/rollbacks.jsonl` after rollback is terminal. |
| `readSummary(home, { sinceDays = 30 })` | Read all three JSONL files plus `state.json`; return one-screen summary structure. |
| `pruneOlderThan(home, days)` | Truncate JSONL files to entries newer than threshold. Atomic via temp + rename. |

## §6 Schema-stability addendum

v0.4 adds these stable surfaces. Each will be documented in
`docs/schema-stability.md` (T-700):

**Report schema** (`schemaVersion: "0.1"`, unchanged):
- Optional field `Finding.falsePositiveSeenBefore: number` (additive; absent when zero).

**Operation manifest schema** (`schemaVersion: "0.2"`, unchanged):
- Optional field `parentStreamId: string` (additive; on sub-manifests within a stream).
- Optional field `streamId: string` (additive; on parent stream manifests).
- Optional field `chunks: string[]` (additive; on parent stream manifests).
- Optional field `streamPartial: true` (additive; only on halted streams).

**Learning schema** (`learnSchemaVersion: "0.4"`, NEW LINE):
- Each JSONL entry carries `learnSchemaVersion: "0.4"`, `ts: ISO8601`, plus type-specific fields.
- `refusals.jsonl`: `{ refusalClass, reason, detectorId?, path?, opIdAttempted? }`
- `applied.jsonl`: `{ opId, detectorIds, paths, finalStatus, durationMs }`
- `rollbacks.jsonl`: `{ rollbackOpId, sourceOpId, finalStatus, reason }`
- `state.json`: `{ learnSchemaVersion: "0.4", counters: {…}, falsePositives: [{detectorId, path, opId, ts}, …] }`

**Lock history schema** (carries `learnSchemaVersion: "0.4"` for unity):
- `lock.history`: `{ learnSchemaVersion: "0.4", ts, pid, action: "acquire"|"release", holder, releaseReason? }`

**Mutation registry kinds documented stable:**
- `json-rewrite` (NEW in v0.4)
- `settings-rewrite` (v0.3, now aliased to `json-rewrite`)
- `file-unlink` (v0.2 Phase 10)
- `dir-rmtree` (v0.2)

**Config schema** (`<home>/.claude/housekeeper/config.json`):
- New optional field `pruneGraceDays: number` (default 30).

## §8 What v0.4 does NOT include

Carry-forward from PLAN §1:

- Multi-home / fleet support (not scheduled)
- Interactive TTY consent (v1.0)
- Auto-rollback of partial-apply batches (v1.0; v0.3 Q3 ruling holds)
- Cross-detector batch composition (v0.5; kept disjoint per v0.3 C6)
- `learn` suggestion engine (v0.5; v0.4 records only)
- Plugin install via `prune --reverse` (v1.0; prune is uninstall-only)

New exclusions surfaced during synthesis:

- **Plugin uninstall mutation (PQ-2).** v0.4.0 is audit-only. Mutation
  ships in v0.4.1 after a data-collection window.
- **ConfigChange auto-reload (PQ-4).** No Claude-side reload event is
  documented. RELOAD HINT block continues from v0.3.
- **Wider exotic-filesystem coverage (PQ-3).** v0.3's
  `settings-network-filesystem` refusal class continues unchanged.
- **Skill-index canonicalization (PQ-1).** Phase 3 reads what the audit
  already classifies; codification waits for runtime verification.
- **`comment-json` parser path.** Q4 chose `jsonc-parser`. The
  comment-json branch is not retained.
- **Per-pillar mutation kinds.** Q2 chose generalization to
  `json-rewrite`. Three per-pillar kinds (`registry-rewrite`,
  `hooks-rewrite`, `skills-rewrite`) are not introduced.
- **Stream resume.** Halted streams must be rolled back and re-run.
  Resume deferred to v0.5 with refusal class `stream-resume-not-supported`.
